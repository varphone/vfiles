# Protocol compatibility audit

Use this register to turn protocol review into a repeatable loop: discover a
concrete issue, record its evidence and priority, fix one item, run the relevant
checks, and record the commit that closes it.

## Findings

| ID | Protocol | Finding and evidence | Priority | State |
| --- | --- | --- | --- | --- |
| HTTP-001 | HTTP | CORS previously allowed only `Accept` and `Content-Type`, blocking browser preflight for Bearer auth and conditional/range downloads; successful responses also hid validators and range metadata from browser JavaScript. Explicit request and exposed response headers plus preflight/206 regression coverage are now in place. | P1 | Fixed in this cycle |
| HTTP-002 | HTTP | Search queries joined every historical version, duplicating filename matches and allowing obsolete overwritten content to match. Both joins now select only the maximum version; a replacement-upload regression test covers unique results and current-content semantics. | P1 | Fixed in this cycle |
| HTTP-003 | HTTP | Multipart routes disable Axum's default body limit to stream large files, but `path` and `message` metadata fields used `Field::bytes()` and could allocate an unbounded field in memory. Metadata fields now stream with a 64 KiB cap; an end-to-end oversized-path test verifies a structured rejection and temporary-file cleanup. | P1 | Fixed in this cycle |
| HTTP-004 | HTTP | Thumbnail revalidation matched only one exact `If-None-Match` value. It missed RFC weak comparison, entity-tag lists and repeated field lines, causing unnecessary image regeneration/downloads on valid cache validators. It now uses the shared conditional-header parser; endpoint regression coverage checks weak, list and repeated-field matches. | P1 | Fixed in this cycle |
| DAV-001 | WebDAV | `Overwrite` was parsed case-sensitively. RFC 4918 defines `T`/`F` as ABNF string literals, which are case-insensitive; a compliant lowercase `f` was rejected. Parser and request-level regression coverage added. | P1 | Fixed: `b8accb2` |
| DAV-002 | WebDAV | `lockinfo` parsing selected the first lock-scope and accepted extra choices, so malformed input containing both `<exclusive/>` and `<shared/>` could be silently granted as exclusive. Parsing now requires exactly one scope choice and one write lock type; unit regressions cover ambiguity. | P1 | Fixed in this cycle |
| DAV-003 | WebDAV | Basic authentication called `verify_credentials` directly and bypassed the shared HTTP/FTP failed-login limiter, allowing unlimited password guesses. WebDAV now counts failures by socket peer IP and normalized login, blocks at the configured threshold with 429/`Retry-After`, clears the counter after success, and records failed attempts in shared login stats. An end-to-end test verifies blocking and that another peer IP remains independent. | P1 | Fixed in this cycle |
| DAV-004 | WebDAV | `DAV:displayname` was treated as a path rename and rejected legal free-text values. RFC 4918 §15.2 defines it as a writable presentation property (`SHOULD NOT` be protected); PROPPATCH now stores it as a dead property, PROPFIND returns the override, and the resource URL remains unchanged. End-to-end coverage sets a value containing `/`, reads it back, and continues to access the original URL. | P1 | Fixed in this cycle |
| DAV-005 | WebDAV | `PROPPATCH DAV:displayname` used the XML element's first text-like node, which included comment text but dropped later text nodes; embedded elements were silently truncated although the property is `(#PCDATA)`. Parsing now concatenates text nodes around comments and rejects nested elements; parser regressions cover both cases. | P1 | Fixed in this cycle |
| DAV-006 | WebDAV | Successful MOVE left lock records attached to the old source URL and an overwritten destination URL, where they could incorrectly block resources later created at those paths. MOVE now removes locks rooted in the moved source subtree and overwritten destination subtree after success; an end-to-end SQLite regression verifies both lock records disappear. | P1 | Fixed in this cycle |
| DAV-007 | WebDAV | PROPFIND accepted only the first selector and silently discarded additional selectors, including the RFC 4918 `allprop` + `include` form. It now parses the optional include list, returns supported properties through the common all-properties response and reports requested absent properties with 404; parser, serializer, and end-to-end regressions cover the behavior. | P1 | Fixed in this cycle |
| DAV-008 | WebDAV | UNLOCK stripped any number of leading/trailing angle brackets and accepted bare token strings, although `Lock-Token` is a single coded URI. Parsing now requires one bracketed valid URI; unit and end-to-end regressions verify a malformed bare copy of a live token returns 400 and leaves the lock available for a subsequent valid UNLOCK. | P1 | Fixed in this cycle |
| DAV-009 | WebDAV | State-token validation accepted URI fragments in `If` and `Lock-Token`, although RFC 4918 requires a Coded-URL containing an RFC 3986 absolute-URI, whose grammar excludes fragments. Raw fragments are now rejected while query components and percent-encoded `%23` remain valid; unit and UNLOCK end-to-end regressions cover both parsers. | P1 | Fixed in this cycle |
| RSYNC-001 | RSYNC | Receiver-side `mkdir` and upload failures were logged and swallowed, so a real rsync sender could receive a successful exit despite rejected data. Errors now terminate the daemon session; the real-client probe creates a file/directory path conflict, requires a nonzero sender exit, and verifies the existing directory remains intact. | P1 | Fixed in this cycle |
| RSYNC-002 | RSYNC | `--delete` ran after the protocol's final completion exchange; database deletion failures were logged and swallowed, and a later connection error could not change rsync's already successful exit. Delete validation/list/filter/storage errors now send a multiplexed `MSG_ERROR` before the completion exchange; the real-client probe injects a SQLite delete trigger failure and verifies a nonzero exit plus preserved stale and newly uploaded entries. | P1 | Fixed in this cycle |
| S3-001 | S3 | `DeleteObjects.LastModifiedTime` was compared with immutable entry creation time, so a correct condition from `HeadObject` failed after overwriting an object. It now batches current version lookup and compares against that version timestamp; boto3 verifies stale time rejection and current time acceptance after overwrite. | P1 | Fixed in this cycle |
| S3-002 | S3 | Concurrent same-content uploads could both publish via replacing rename and report `created_blob=true`; if one database commit later failed, its cleanup could remove the blob already referenced by the other committed version. Blob files are now synced before no-clobber hard-link publication, the target directory is synced, and a concurrent streaming-write regression asserts exactly one writer owns cleanup. | P1 | Fixed in this cycle |
| S3-003 | S3 | A process may stop after streaming blob publication but before SQLite records the version. A restart regression closes/reopens SQLite with such an unregistered blob present, then verifies maintenance removes it after the grace period while preserving fresh or referenced blobs. Actual power-loss and filesystem fault injection remain untested. | P1 | Restart recovery path verified; hardware fault injection open |
| S3-004 | S3 | `commit_upload_stream` could return early on a path race or repository error after publishing a new blob, leaving it until delayed maintenance; a failure after creating the file entry could also leave a versionless file. Pre-version failures now remove only resources created by this attempt, and a streaming-upload regression covers a target changed to a directory after session creation. | P1 | Fixed in this cycle |
| S3-005 | S3 | Upload-session metadata completion/read happened after the object version was committed but could still fail the request, prompting retries of an already successful write. Post-commit session state and cleanup are now best-effort; a streaming-reader regression corrupts metadata after session lookup and verifies the committed object returns success. | P1 | Fixed in this cycle |
| S3-006 | S3 | Entry re-read and automatic snapshot creation happened after version commit and could fail the upload response. The entry is now carried forward from pre-commit state, snapshot finalization is best-effort and represented as `mutation: None`, and a SQLite trigger fault-injection regression verifies the object write remains successful. | P1 | Fixed in this cycle |
| S3-007 | S3 | S3 object ETag and user metadata were committed after the object version, so a storage error could leave a committed object with missing validators/metadata and an error response. Put/Copy/multipart now pass version-derived properties into `EntryRepo::create_version_with_properties`; SQLite commits blob reference, version, ETag, metadata replacement and entry timestamp together. Trigger fault injection verifies a property failure rolls back the version, new entry and blob. | P1 | Fixed in this cycle |
| S3-008 | S3 | A malformed credential mode caused startup to log the full `access:secret:namespace:mode` entry, exposing the Secret Key. The warning now omits credential contents; a parser regression preserves the existing read-write fallback for unknown modes. | P1 | Fixed in this cycle |
| S3-009 | S3 | Strict region validation read only the `Authorization` header, allowing query-signed presigned URLs to bypass the configured region check. It now checks s3s's verified `S3Request::region`; boto3 confirms wrong-region presigned URLs return `AuthorizationHeaderMalformed` while matching-region URLs work. | P1 | Fixed in this cycle |
| S3-010 | S3 | `ListObjects(V1/V2)` paginated and delimiter-folded stored entries before removing entries hidden by current delete markers. This could return underfilled or empty truncated pages and `CommonPrefixes` whose only objects were deleted. Listing now filters marker-hidden files during bounded SQL page collection, before pagination and prefix folding; SQLite and boto3 regressions cover both cases. | P1 | Fixed in this cycle |
| S3-011 | S3 | Object keys longer than S3's 1,024-byte UTF-8 limit were accepted by path normalization, while invalid path errors were reported as `InternalError`. Key normalization now enforces the byte limit and maps validation failures to `InvalidArgument`; boundary unit tests cover ASCII and multibyte keys, and the boto3 probe checks the wire status and error code. | P1 | Fixed in this cycle |
| S3-012 | S3 | The S3 key namespace was not injective: `norm()` trimmed leading/trailing slashes and `NormalizedPath` rejected keys with `//` or `..`. S3 now maps non-filesystem keys to a reversible hex-escaped internal path, records the exact external key in a SQLite index, and pages/list-folds by the raw key. SQLite triggers index files created or renamed through HTTP/WebDAV; PUT, Copy and multipart completion bind their external keys. boto3 writes `a`, `/a`, and `a/` with distinct bodies, reads each body independently, lists all three in key order, and verifies exact `a/` prefix filtering. A real WebDAV MOVE of a special-key backing file preserves S3 GET, overwrite, LIST and version history by the original key. The probe also covers `foo..bar` and relative-segment keys at the mapping unit level; WebDAV DELETE and COPY of these backing entries still need client verification. | P1 | Key identity and MOVE verified; remaining cross-protocol mutations open |
| QA-001 | S3 | Independent-client probe: boto3/botocore 1.34.46 passed 54/54 operations, including raw leading/trailing slash key identity, strict-region presigned URL rejection/acceptance, delete-marker-aware delimiter prefixes and pagination; rclone 1.60.1-DEV passed bucket listing, upload, list, download, 11 MiB multipart upload/download byte comparison, delete, Unicode/space/empty keys, checksum check, and upload/list/sync of 1005 objects across the 1000-key page boundary. | P1 | Verified for tested operations |
| QA-002 | WebDAV | cadaver 0.24 passed authenticated MKCOL, PUT, COPY, MOVE, PROPFIND listing, GET byte comparison, DELETE, and collection removal. System litmus passed all 104 basic/copymove/props/locks/http checks, including shared and depth-infinity locks; its two warnings are informational: the HTTP URI parser removes fragments before the DAV handler (so they cannot select a distinct resource there), and litmus expects 423 for a false `If` condition although RFC 4918 §10.4 requires 412. rclone exercises authenticated MKCOL, upload/download, Unicode/space names, content check, MOVE and DELETE. | P1 | litmus, cadaver and rclone probes run in CI; RFC status checked |
| QA-003 | RSYNC | System rsync 3.2.7 protocol 31 passes the isolated daemon probe: module discovery, recursive push/pull with empty directories and a 2 MiB file, single-file download, fixed file modification-time preservation across `-a` push/pull, same-size checksum update sending less literal data than the full file, `--delete --exclude` protection, `--delete-excluded`, failed-upload propagation on a file/directory path conflict, and failed-delete propagation under an injected SQLite failure; pulled trees are compared byte-for-byte. | P1 | Real-client probe runs in CI; broader rsync feature coverage remains open |
| QA-004 | S3 test tooling | The installed botocore 1.34.46 S3 model predates conditional `DeleteObjects` fields and `PutObject`/`DeleteObject` conditions used by the probe. The probe now supplies those missing model members, including RFC 822 timestamp serialization; the complete 50/50 run passes. | P1 | Fixed in this cycle |

## Discovery and verification baseline

- Static analysis: `cargo clippy --workspace --all-targets -- -D warnings`.
- Formatting gate: `cargo fmt --all -- --check`.
- Regression baseline: `cargo test --workspace` plus protocol-specific end-to-end tests.
- Third-party tools found in the current development environment: `curl` 8.5.0,
  `rsync` 3.2.7 (protocol 31), `rclone` 1.60.1-DEV, `cadaver` 0.24,
  `boto3` 1.34.46, `botocore` 1.34.46, and `litmus`.
- Manual client checks in this environment are evidence for the operations
  listed above, not proof of complete protocol conformance. Automate these
  scenarios and add real rsync daemon client coverage to CI as follow-up work.

This is an environment snapshot, not a claim that the listed protocols are
fully conformant. Recheck tool availability and update this register when the
environment or test harness changes.
