# Protocol compatibility audit

Use this register to turn protocol review into a repeatable loop: discover a
concrete issue, record its evidence and priority, fix one item, run the relevant
checks, and record the commit that closes it.

## Findings

| HTTP-001 | HTTP | CORS previously allowed only `Accept` and `Content-Type`, blocking browser preflight for Bearer auth and conditional/range downloads; successful responses also hid validators and range metadata from browser JavaScript. Explicit request and exposed response headers plus preflight/206 regression coverage are now in place. | P1 | Fixed in this cycle |
| HTTP-002 | HTTP | Search queries joined every historical version, duplicating filename matches and allowing obsolete overwritten content to match. Both joins now select only the maximum version; a replacement-upload regression test covers unique results and current-content semantics. | P1 | Fixed in this cycle |
| HTTP-003 | HTTP | Multipart routes disable Axum's default body limit to stream large files, but `path` and `message` metadata fields used `Field::bytes()` and could allocate an unbounded field in memory. Metadata fields now stream with a 64 KiB cap; an end-to-end oversized-path test verifies a structured rejection and temporary-file cleanup. | P1 | Fixed in this cycle |
| HTTP-004 | HTTP | Thumbnail revalidation matched only one exact `If-None-Match` value. It missed RFC weak comparison, entity-tag lists and repeated field lines, causing unnecessary image regeneration/downloads on valid cache validators. It now uses the shared conditional-header parser; endpoint regression coverage checks weak, list and repeated-field matches. | P1 | Fixed in this cycle |
| HTTP-005 | HTTP | Live directory ZIP downloads queried the current version once per file after loading the subtree, adding one SQLite round trip for every file in large archives. The service now batches current version IDs in one `find_versions` call before streaming archive contents; the existing live/version/snapshot archive integration test guards archive contents and sizes. | P1 | Fixed in this cycle |
| HTTP-006 | HTTP | Historical directory ZIP downloads loaded every file's entire history with one query per file, then selected the first version at or before the requested cutoff. They now query only the highest version number at or before the cutoff in 500-entry batches; repository cutoff and end-to-end archive tests cover selection and output. | P1 | Fixed in this cycle |
| HTTP-007 | HTTP | Axum/Hyper's URI parsing stripped a raw fragment from an HTTP/1.1 origin-form request-target before application middleware could inspect it. A raw `DELETE /dav/fragcol#fragment` was handled as `DELETE /dav/fragcol` and deleted the collection; HTTP/2's h2 parser likewise truncated `:path` fragments. Vendored Hyper 1.11.0 now rejects `#` in the HTTP/1 request target, and vendored h2 0.4.19 rejects it in `:path` before `http::Uri/PathAndQuery` normalization. Hyper's request decoder regression and h2's full request-conversion regression reject raw fragments while preserving encoded `%23` and query paths. System litmus now passes its fragment DELETE check with no unsafe-delete warning, and the probe fails if that warning returns. | P1 | Fixed in this cycle |
| HTTP-008 | HTTP | Multipart upload disables Axum's default body limit so large file fields can stream. Although individual `path` and `message` fields had byte limits, unlimited unknown or repeated metadata fields could make the request body arbitrarily large. The parser now caps the form at 16 fields and all non-file field data at 256 KiB total (64 KiB each), including ignored extension fields; endpoint regressions verify byte/count rejection and temp-file cleanup. | P1 | Fixed in this cycle |
| HTTP-009 | HTTP | `POST /api/files/directories` created a directory, then loaded every child of its parent to find the new entry for the response. Creating one directory in a large parent therefore did work and allocated memory proportional to the parent's full listing. The route now fetches the created entry directly by namespace and normalized path; the existing authenticated API regression verifies the returned entry and materialized parent behavior. | P1 | Fixed in this cycle |
| HTTP-010 | HTTP | Thumbnail requests used `read_file_bytes` before checking the 40 MiB source limit, ETag, or disk cache, so rejected large images and 304/cache-hit requests still read and allocated the complete source. The route now opens a stream, validates metadata and conditional/cache state first, then reads at most declared size plus one byte only for a cache miss; it rejects a mismatch between bytes read and stored size. Thumbnail generation, cache and conditional-request integration coverage exercises the updated path. | P1 | Fixed in this cycle |
| HTTP-011 | HTTP | Content search used `AsyncBufRead::lines()`, which allocated an entire newline-free line, then lowercased and retained every matching line in the response. A large text blob or highly repetitive file could therefore drive unbounded per-request memory. Search now scans fixed 8 KiB chunks with incremental UTF-8 validation and Unicode lowercase matching, retains at most 20 matches per file and a bounded snippet around each hit, and reports `matches_truncated` / `context_truncated` in the response. Large-line, chunk-boundary, invalid-UTF-8 and repeated-match unit tests plus an HTTP endpoint regression cover the limits and fields. | P1 | Fixed in this cycle |
| HTTP-012 | HTTP | Content search opened and scanned up to 500 candidate blobs sequentially, making filesystem latency add across every candidate. Candidate scans now overlap with at most eight active blob streams per shared `SqliteSearchRepo` semaphore; `SearchService` continues sorting by score and path before pagination, so completion order does not affect pages. A concurrency regression measures the shared permit ceiling and the HTTP page-walk test verifies result continuity. | P1 | Fixed in this cycle |
| DAV-001 | WebDAV | `Overwrite` was parsed case-sensitively. RFC 4918 defines `T`/`F` as ABNF string literals, which are case-insensitive; a compliant lowercase `f` was rejected. Parser and request-level regression coverage added. | P1 | Fixed: `b8accb2` |
| DAV-002 | WebDAV | `lockinfo` parsing selected the first lock-scope and accepted extra choices, so malformed input containing both `<exclusive/>` and `<shared/>` could be silently granted as exclusive. Parsing now requires exactly one scope choice and one write lock type; unit regressions cover ambiguity. | P1 | Fixed in this cycle |
| DAV-003 | WebDAV | Basic authentication called `verify_credentials` directly and bypassed the shared HTTP/FTP failed-login limiter, allowing unlimited password guesses. WebDAV now counts failures by socket peer IP and normalized login, blocks at the configured threshold with 429/`Retry-After`, clears the counter after success, and records failed attempts in shared login stats. An end-to-end test verifies blocking and that another peer IP remains independent. | P1 | Fixed in this cycle |
| DAV-004 | WebDAV | `DAV:displayname` was treated as a path rename and rejected legal free-text values. RFC 4918 §15.2 defines it as a writable presentation property (`SHOULD NOT` be protected); PROPPATCH now stores it as a dead property, PROPFIND returns the override, and the resource URL remains unchanged. End-to-end coverage sets a value containing `/`, reads it back, and continues to access the original URL. | P1 | Fixed in this cycle |
| DAV-005 | WebDAV | `PROPPATCH DAV:displayname` used the XML element's first text-like node, which included comment text but dropped later text nodes; embedded elements were silently truncated although the property is `(#PCDATA)`. Parsing now concatenates text nodes around comments and rejects nested elements; parser regressions cover both cases. | P1 | Fixed in this cycle |
| DAV-006 | WebDAV | Successful MOVE left lock records attached to the old source URL and an overwritten destination URL, where they could incorrectly block resources later created at those paths. MOVE now removes locks rooted in the moved source subtree and overwritten destination subtree after success; an end-to-end SQLite regression verifies both lock records disappear. | P1 | Fixed in this cycle |
| DAV-007 | WebDAV | PROPFIND accepted only the first selector and silently discarded additional selectors, including the RFC 4918 `allprop` + `include` form. It now parses the optional include list, returns supported properties through the common all-properties response and reports requested absent properties with 404; parser, serializer, and end-to-end regressions cover the behavior. | P1 | Fixed in this cycle |
| DAV-008 | WebDAV | UNLOCK stripped any number of leading/trailing angle brackets and accepted bare token strings, although `Lock-Token` is a single coded URI. Parsing now requires one bracketed valid URI; unit and end-to-end regressions verify a malformed bare copy of a live token returns 400 and leaves the lock available for a subsequent valid UNLOCK. | P1 | Fixed in this cycle |
| DAV-009 | WebDAV | State-token validation accepted URI fragments in `If` and `Lock-Token`, although RFC 4918 requires a Coded-URL containing an RFC 3986 absolute-URI, whose grammar excludes fragments. Raw fragments are now rejected while query components and percent-encoded `%23` remain valid; unit and UNLOCK end-to-end regressions cover both parsers. | P1 | Fixed in this cycle |
| DAV-010 | WebDAV | PUT `If-Match` removed ETag quotes before comparing, so weak tags and malformed bare values could pass as strong matches; it also read only the first repeated field line and treated a lookup error as a missing representation. It now uses RFC strong comparison, parses quoted comma-containing tags, combines repeated field lines, distinguishes resource existence from ETag presence, and maps repository failures to 500. Unit and authenticated route tests cover weak/bare tags, repeated fields and wildcard existence. | P1 | Fixed in this cycle |
| DAV-011 | WebDAV | PUT ignored the HTTP preconditions `If-Unmodified-Since` and `If-None-Match`, allowing stale clients to overwrite a changed resource or overwrite when the client required absence. It now evaluates `If-Match`, then `If-Unmodified-Since` only when `If-Match` is absent, then weak `If-None-Match`, returning 412 when a condition fails. Authenticated route regressions cover stale/future dates, weak matching tags, nonmatching tags, and precedence. | P1 | Fixed in this cycle |
| DAV-012 | WebDAV | PUT evaluated HTTP preconditions before reading a potentially long request body, then committed without checking whether the resource changed during upload. Conditional PUT now carries the observed entry/version snapshot into SQLite and checks the path identity and current version in the same `BEGIN IMMEDIATE` transaction that creates the new version. A streaming-upload regression changes the current version after capturing the condition and verifies the stale write returns 412 without adding a version. | P1 | Fixed in this cycle |
| DAV-013 | WebDAV | DELETE ignored HTTP representation preconditions, so a stale client could remove a newer representation after its earlier check. DELETE now evaluates strong `If-Match`, `If-Unmodified-Since` when `If-Match` is absent, and weak `If-None-Match`; SQLite compares the observed entry/version snapshot and deletes in one transaction. Application and route regressions verify changed-version rejection and a stale `If-Match` returning 412. | P1 | Fixed in this cycle |
| DAV-014 | WebDAV | DELETE and MOVE ignored `Depth`; a request with `Depth: 0` or `Depth: 1` could still recursively delete or move a collection. They now reject malformed/repeated `Depth` fields, and reject non-`infinity` values for collection targets while retaining standard `0`/`1` syntax parsing. Unit and route regressions cover collection DELETE and MOVE. | P1 | Fixed in this cycle |
| DAV-015 | WebDAV | MOVE ignored HTTP representation preconditions and could move a source whose validator no longer matched. It now evaluates the same `If-Match` / date / `If-None-Match` conditions as DELETE and passes the observed entry/version snapshot to the SQLite move transaction, including overwrite replacement. An application regression proves stale source rejection preserves both source and destination; the route regression verifies stale `If-Match` returns 412. | P1 | Fixed in this cycle |
| DAV-016 | WebDAV | COPY ignored HTTP representation preconditions. It now evaluates the source validators and, when conditions are present, captures the source subtree under the same SQLite read snapshot as the atomic entry/version comparison before copying that captured tree. Regressions verify stale-source rejection preserves the overwrite target, current-version COPY succeeds, and the route returns 412 for stale `If-Match`. | P1 | Fixed in this cycle |
| DAV-017 | WebDAV | MKCOL checked only exact body size hints plus `Transfer-Encoding`; an unknown-length streamed body (as carried by HTTP/2) could be treated as empty and create a collection despite unsupported request content. MKCOL now probes unknown-length bodies with a one-byte bound and rejects non-empty or unreadable bodies with 415. The WebDAV e2e regression sends a streamed body without `Content-Length` and verifies no collection is created. | P1 | Fixed in this cycle |
| DAV-018 | WebDAV | PUT checked active locks before streaming its request body but did not recheck them when committing the new version, so a lock acquired during a long upload could be bypassed. PUT now carries the observed covering lock-token set into the SQLite `BEGIN IMMEDIATE` version transaction and rejects the commit with 412 if that set changed. A repository regression injects a new active lock after the precheck and verifies the current version remains unchanged; litmus, cadaver and rclone cover normal lock and write interoperability. | P1 | Fixed in this cycle |
| DAV-019 | WebDAV | Write-lock checks for PUT, PROPPATCH, DELETE, MOVE and COPY originally ended before their storage mutation committed, allowing a newly acquired lock to race the request. These operations now carry observed token snapshots into their SQLite write transaction; recursive DELETE/MOVE and COPY overwrite also snapshot locked descendant paths, and MOVE/COPY validate destination locks before replacing data. Transaction regressions acquire locks after the simulated precheck and verify that entry state and overwritten targets remain unchanged. | P1 | Fixed in this cycle |
| DAV-020 | WebDAV | The shared-listener WebDAV router was nested after the HTTP router's CORS layer and therefore did not inherit that middleware. Browser clients' preflight requests for `PROPFIND`/`LOCK` and headers such as `Depth`, `Destination`, `If` and `Lock-Token` could not reach WebDAV. The common CORS policy now lists DAV methods and request/response headers, and the shared-port mount applies the policy directly to the nested WebDAV router. An actual mounted-route probe validates the preflight before running cadaver. | P1 | Fixed in this cycle |
| DAV-021 | WebDAV | PROPPATCH stored custom dead-property XML by recursively traversing and serializing the parsed element tree. The 1 MiB body cap did not bound nesting depth, so crafted input could exhaust the request task's stack. Parsing now iteratively rejects dead-property trees deeper than 128 elements before entering recursive serialization; boundary regressions accept depth 128 and reject depth 129. | P1 | Fixed in this cycle |
| DAV-022 | WebDAV | `tower-http::CorsLayer` short-circuits all `OPTIONS` requests, not only browser preflights. On the shared listener this removed `DAV` and `Allow` from ordinary WebDAV capability discovery; Litmus then skipped Class 2 lock checks and marked `basic/options` failed. An outer WebDAV middleware restores capability headers on OPTIONS responses, and the real-server probe now checks those headers before Litmus. | P1 | Fixed in this cycle |
| DAV-023 | WebDAV | PROPFIND rejected `Depth: infinity` and the RFC default (an omitted `Depth`) with 403, which prevented clients from recursively discovering large directory trees. It now returns the target and all descendants, loads versions/custom properties/locks in batches, preserves absolute descendant hrefs, and accepts case-insensitive `infinity`. SQLite-backed regressions cover root default depth, nested subtree scope, and Depth 1 isolation. | P1 | Fixed in this cycle |
| DAV-024 | WebDAV | `PROPFIND Depth: 1` fetched every direct child into one `Vec`, unlike the paged `Depth: infinity` path; a single large collection therefore caused unbounded per-request entry and metadata memory. It now reads bounded 256-entry pages using a directory-first SQLite keyset cursor and batches file metadata per page. An authenticated SQLite-backed regression traverses 1,042 children across directory and file cursor boundaries, checks the first/last entries and file properties; litmus, cadaver and rclone probes remain green. | P1 | Fixed in this cycle |
| DAV-025 | WebDAV | `Depth: infinity` fetched database rows and metadata in 256-entry pages but appended every serialized page to one response `String`, so memory usage still grew with the full recursive tree. PROPFIND now writes each bounded XML page to an anonymous temporary file and sends the completed file as an async stream; storage/query failures occur before response headers are sent. The SQLite end-to-end test verifies a 1,042-descendant infinity response across multiple pages, and the full litmus suite passes. | P1 | Fixed in this cycle |
| RSYNC-001 | RSYNC | Receiver-side `mkdir` and upload failures were logged and swallowed, so a real rsync sender could receive a successful exit despite rejected data. Errors now terminate the daemon session; the real-client probe creates a file/directory path conflict, requires a nonzero sender exit, and verifies the existing directory remains intact. | P1 | Fixed in this cycle |
| RSYNC-002 | RSYNC | `--delete` ran after the protocol's final completion exchange; database deletion failures were logged and swallowed, and a later connection error could not change rsync's already successful exit. Delete validation/list/filter/storage errors now send a multiplexed `MSG_ERROR` before the completion exchange; the real-client probe injects a SQLite delete trigger failure and verifies a nonzero exit plus preserved stale and newly uploaded entries. | P1 | Fixed in this cycle |
| RSYNC-003 | RSYNC | Recursive pulls queried child metadata separately for each directory, making database round trips grow with directory count. Recursive flist collection now fetches the requested subtree, current version metadata and source mtimes in one indexed SQLite query, then reconstructs the same depth-first listing order in memory. Repository regressions cover subtree isolation, file and directory mtimes, and root-level names; the real rsync 3.2.7 recursive push/pull probe passes. | P1 | Fixed in this cycle |
| RSYNC-004 | RSYNC | Flist decoding consumed and discarded symlink target bytes, while flist encoding had no symlink target field. Pull restores links from the marker. History restore now restores the versioned type and synchronizes the current marker transactionally. The HTTP download probe confirms consumers receive target bytes, and WebDAV PROPFIND filters the internal marker. Real rsync 3.2.7 verifies file-to-link-to-file replacement and link pull; an app regression covers both symlink and regular-file history restores. | P1 | Fixed; push/pull and restore regression verified |

## Discovery and verification baseline

- Static analysis: `cargo clippy --workspace --all-targets -- -D warnings`.
- Formatting gate: `cargo fmt --all -- --check`.
- Regression baseline: `cargo test --workspace` plus protocol-specific end-to-end tests.
- Third-party tools found in the current development environment: `curl` 8.5.0,
