# HTTP 性能审核与优化记录

本文记录 HTTP 性能审核、已实施的改进和仍需结合部署负载判断的事项。审核基线来自 v2.6.11 代码；下方数字来自本地回环、合成数据或临时对照测试，不能作为生产环境 SLA。数据库设备、操作系统缓存、网络、请求分布和并发模型都会改变结果。

## 已实施的改进

| 问题 | 审核证据 | 改进 | 验证 |
| --- | --- | --- | --- |
| HTTP/2 小包发送延迟 | 本地复用连接请求 27.6 KB 目录 JSON 时，HTTP/2 总耗时 p50 为 45.42 ms、p95 为 46.89 ms；临时启用 `TCP_NODELAY` 后分别为 2.43 ms、3.65 ms。HTTP/1 对照 p50 为 2.35 ms 和 2.05 ms。 | 接受 TCP 连接后启用 `TCP_NODELAY`。设置失败时记录警告，不中断连接接入。 | `http_server::tests::accepted_streams_enable_tcp_nodelay` 检查 socket 选项；HTTP 服务端测试覆盖连接上限、超时和 HTTP/2 设置。 |
| 目录选择器 COUNT 扫描 | 100,000 条目数据集上，查询计划此前按命名空间扫描非覆盖索引。临时复合索引对照测试的 40 次串行请求中，p50 从 28.74 ms 降至 2.27 ms，p95 从 32.16 ms 降至 3.70 ms。 | 添加只包含目录的部分索引，并为根目录目录计数添加更窄的部分索引。 | 查询计划测试要求目录计数使用覆盖索引；完整 SQLite 测试覆盖迁移。 |
| 文件名子串搜索扫描 | 临时 SQLite 3.45.1、300,000 条路径对照：紧凑 trigram 索引将无匹配查询 p50 从 27.13 ms 降至 0.22 ms，将 20 项匹配查询从 24.93 ms 降至 0.10 ms；1,000 项匹配查询从 28.97 ms 降至 8.16 ms。完整细节索引额外占 32.6 MiB；`detail=none` 索引额外占 13.4 MiB（基础数据库 32.6 MiB）。 | 新增默认关闭的 `VFILES_SEARCH_FILENAME_TRIGRAM_INDEX=true`。启用后对路径建立紧凑 trigram 候选索引，仍用原 `LOWER(path) LIKE ... ESCAPE` 精确复核，短查询回退原查询；插入、删除、路径更新由事务触发器维护。 | SQLite 集成测试比较索引与原查询的路径结果（大小写、Unicode、引号、LIKE 通配符和短查询），验证目录范围过滤、查询计划使用 FTS 虚表索引、索引创建/重开/更新/删除/关闭。默认仍关闭：合成 5,000 条插入中位耗时从 15.6 ms 增至 111.5 ms（约 7.17 倍），适合读多写少并愿意用写入速度和约 41% 路径数据库空间换搜索延迟的部署。 |
| 根目录总数扫描与深 `offset` 分页 | 100,000 条目数据集中，`offset=0` 的根列表 p50 为 8.63 ms、p95 为 10.87 ms；`offset=99900` 的 p50 为 21.39 ms、p95 为 25.39 ms。并发 32 时，浅页 p50 / p95 约为 102 / 168 ms，深页约为 186 / 247 ms。根总数查询此前扫描命名空间下所有路径。 | 根条目总数改用只含直接子项的覆盖部分索引。HTTP 实时目录列表增加 `(kind, path)` 游标分页；根目录和嵌套目录的续页查询按游标路径 seek 对应的部分索引。目录游标先取后续目录，页未填满时再补文件。客户端「加载更多」在服务端提供游标时使用游标；`offset` 参数仍供兼容调用方使用。 | SQLite 查询计划测试验证根计数索引，以及根目录、根文件和嵌套目录游标的路径范围 seek；HTTP API 测试覆盖目录优先顺序、跨目录到文件的游标切换、连续分页、越界游标拒绝和非法游标。客户端 store 测试验证续页使用游标。 |
| 已压缩文件重复压缩 | 70 MB 目录压缩包本地构建约需 1 秒；审核代码对所有归档文件使用 Deflate。 | JPEG、PNG、WebP、AVIF、常见音视频、字体和压缩包等已压缩格式写入 ZIP 时使用 `Stored`；文本等其他格式继续使用 `Deflated`。普通 GET 流式生成归档；Range 和条件请求回退到临时文件。 | 应用服务测试检查 JPEG 使用 `Stored`、文本使用 `Deflated`；归档测试验证两种路径中的 ZIP 内容可读。 |
| 普通目录下载的首字节延迟与临时文件 I/O | 原流程必须等完整 ZIP 写入临时文件后才能开始 HTTP 响应；70 MB 本地归档生成约需 1 秒，并额外写入再读取整包临时数据。 | 普通 GET 和公开分享 GET 使用 `ZipWriter::new_stream` 直接生成有界响应流，输出通道容量为 2、缓冲块为 64 KiB。响应不声明未知的 `Content-Length`，也不宣传 Range；带 `Range` 或条件请求继续使用临时文件路径，保留完整长度与现有 206 / 条件响应语义。 | 应用服务测试读取并解开流式 ZIP；HTTP 集成测试覆盖普通下载、公开分享、缺省长度和 Range 回退。流式生成时的后续 blob 错误会作为响应体错误结束传输，服务端记录警告。 |
| 预压缩静态资源的冗余打开 | 文件系统静态资源命中 `.br` 或 `.gz` 时，旧流程会先打开未压缩文件，再打开编码变体。 | 先尝试客户端可接受的 `.br`、`.gz` 变体；变体未命中时再打开未压缩文件。仍对每个文件执行 canonical path 检查。 | 静态资源测试覆盖仅有压缩变体、编码协商、拒绝未压缩内容和越界符号链接。 |
| 每个 HTTP 请求写两条访问日志 | 本地每秒 1,000 次健康检查的对照中，默认日志约 9,517 req/s，关闭 INFO 后约 9,585 req/s；p95 分别为 0.111 ms 和 0.086 ms。默认日志约为每 1,000 个请求 234 KB。 | 合并为一条结构化完成事件，记录请求 ID、方法、脱敏路径、状态码和 `response_ready_us`。该时长到 handler 返回响应为止，不代表响应体传输完成时间。 | 请求日志测试捕获 tracing event，要求每个请求只写一条事件并包含时长字段；原有凭据脱敏测试继续运行。 |

目录计数索引缩小了扫描范围，但会增加少量索引存储和条目写入成本。游标分页消除了分页查询对先前页行数的重复跳过；为保持现有「已加载数量 / 总数」界面，游标请求仍查询精确总数。根目录计数现在只扫描根条目索引，条目数很大的根目录仍会产生与根条目数相关的计数工作。

## 已评估并保留现状的优化项

| 项目 | 当前证据 | 处理依据 |
| --- | --- | --- |
| 连接池和并发上限调优 | HTTP 活跃连接上限为 512、HTTP/2 单连接并发流上限为 32、API 处理许可为 128；SQLite 最大连接数明确固定为 10。256 个并发 HTTP/1 大列表请求中，206 个返回 200、50 个快速返回 429，突发后请求恢复为 200。另在 100,000 条目合成库上重复两轮连接池矩阵：10→20 个连接使 128 个并发「根计数 + 取 100 行」请求 p50 中位数约从 153 ms 降至 138 ms、p95 从 163 ms 降至 150 ms；64 个并发插入的 p50 从 6.6 ms 升至 11.3 ms、p95 从 19.6 ms 升至 47.9 ms，批次耗时中位数从 56 ms 升至 108 ms。40 个连接读延迟更高、插入 p95 进一步变差。池容量测试验证当前上限为 10。 | 保留 10 个连接作为混合读写折中。20 个连接的读延迟收益约 8% 至 10%，但写入 p95 超过 2 倍、插入批次耗时接近 2 倍；SQLite WAL 仍只有一个写入者，连接增加会加重锁争用。HTTP 并发许可提供过载边界，无证据支持统一提高服务级限制。 |
| API 列表、搜索和历史响应缓存 | API JSON 默认使用 `private, no-store`；文件和缩略图使用 `private, no-cache` 并支持条件请求。集成测试验证 session、目录列表、搜索和令牌响应的策略。 | 保留当前策略。列表、搜索和历史结果依赖用户、命名空间、目录和版本状态；缓存命中仍需生成或验证实体标签，并维护跨修改路径的失效规则。没有服务器 CPU 瓶颈证据支持增加这些工作。 |
| 静态资源缓存与前端包体 | 带哈希的资源缓存一年并标记 immutable，`index.html` 使用 `no-cache`。当前构建检查通过；Brotli 为 804.6 / 833.8 KB、gzip 为 878.1 / 912.6 KB、未压缩为 1,927.3 / 2,026.1 KB，均已使用约 95% 至 97% 的现有预算。 | 保持当前缓存策略和体积检查。缓存已经利用资源哈希保证版本隔离；包体余量较小，新增依赖前继续检查预算。 |
| 根目录精确总数的维护计数 | 100,000 条目对照中，根列表 p50 / p95 为 8.63 / 10.87 ms；计数查询计划已使用只含根条目的覆盖部分索引。并发 32 时整页 p50 / p95 为 102 / 168 ms。 | 保留每页精确计数。串行计数成本已低，维护计数会要求所有创建、删除、移动、批量导入和回滚路径原子更新同一状态；目前没有证据证明它能抵消一致性成本。 |

普通归档 GET 已改为流式输出；Range、条件请求仍用临时文件生成。上表已逐项记录其余候选的本地数据和保留现状的理由。文件名 trigram 索引提供默认关闭的开关，启用前应安排回填时间并确认磁盘余量和写入比例。

## 当前关键资源限制

| 资源 | 当前限制或行为 |
| --- | --- |
| HTTP 连接 | 最多 512 个活跃连接；超限的新连接会关闭。 |
| HTTP/2 | 每个连接最多 32 个并发 stream；接受的 TCP socket 启用 `TCP_NODELAY`。 |
| API 处理 | 全局 API 处理许可为 128；饱和时快速返回过载响应。 |
| SQLite | WAL、`synchronous=NORMAL`、5 秒 busy timeout；连接池最大连接数为 10。 |
| 前端静态文件 | 文件系统模式按请求 canonicalize 文件并检查其仍处于前端根目录下；优先读取预压缩文件。 |
| ZIP 归档 | 普通 GET 使用容量为 2 的有界响应 channel 和 64 KiB 块；Range / 条件请求会完整写入临时文件，以提供已知长度和 seek。 |

不要只根据并发请求数提高连接、stream 或 API 许可。SQLite 写入能力、文件系统吞吐、CPU 和内存都会限制实际容量。

## 回归验证

针对代码修改运行对应的定向测试：

```bash
cargo test -p vfiles-bin --bin vfiles http_server::tests
cargo test -p vfiles-infra-sqlite tree_page_query_plan_tests
cargo test -p vfiles-app
cargo test -p vfiles-http --test api_endpoints
cd client && bun run check
```

发布前还需运行 workspace 回归、前端构建和包体预算检查：

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd client && bun run build && bun run size:check
```

本地对照测试仅用于确认趋势。发布后应使用部署环境的真实目录规模、网络协议、文件类型和并发分布复测；记录 p50、p95、错误率、429 比例、SQLite 写延迟和归档首字节时间。
